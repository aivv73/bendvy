# Registered systems over retained owners

These consumers retain the modern semantic cases while execution returns to one
sequential owner path. Gameplay receives declared capabilities; the library
registers actual system owners, derives their access metadata, and returns their
World, Local, cursors, and completions.

| Entry | Semantic case |
| --- | --- |
| `main.bend` | Two physical storage halves, writes followed by a body error, foreign-World refusal |
| `scheduled.bend` | Sealed registration and dependency scheduling |
| `overlap.bend` | Three systems, two sharing actual Position and Counter owners |
| `overlap-conditions.bend` | Registered condition reads, disabled outcomes, and retained condition Local |
| `overlap-getters.bend` | Reads through writable capabilities without changing owner stamps |
| `overlap-refusal.bend` | Foreign World refuses original owners and retains their Local and cursors |
| `overlap-entry.bend` | Focused same-owner scheduling scenario |
| `query-entry.bend` | Query updates and deferred commands over actual affine owners |

The complete observers include physical slots, payload tokens, cached values,
lifecycle stamps, capacities, resources, Local, cursors, live handles, allocator
state, registration metadata, clock, namespace, pending commands, and events.
Getter scenarios retain the original last-write expectation rather than treating
reads as writes. Handled errors retain the writes made before completion.

Parallel-policy diagnostic entry points have been removed. The ordinary
application and five scheduling entries pass source checks and complete
JS/native observation comparisons. The condition expectation records the
sequential rule: evaluate its condition immediately before its bound system.
The query entry uses the migrated whole-owner command-query implementation;
its focused wrapper has no separate runtime qualification here. The overlap
entry selects Schema A from the existing overlap scenario.
Historical worker and
reference-output evidence belongs to its original source and artifacts. It does
not qualify this sequential implementation, and the approved helper proofs do
not establish whole-engine ownership or execution correctness.
