# Save and restore ownership boundary

Save and restore retain the actual sequential application and its affine owners.
The migration changes application representation, not persistence eligibility,
admission, recovery or receiver ownership. Changed consumers still require
integrated qualification.

The approved `pending_returns_actual_application` law remains scoped to unchanged
`Gate.checked`. A supplied True pending flag returns the same actual application
and RefusedPending without projection. It does not prove the pending detector,
whole-World identity, restore or refinement. Other persistence draft laws remain
unapproved; prior helper proofs retain their original scope.

## Save admission and projection

The save plan binds actual canonical Layout, nominal declarations, codecs and
projection. Plain, Transient and Constructed retain access policy independently
of persistence kind. Representing a protected resource supplies no restore grant.

The scheduled adapter inspects actual command buffers before World projection.
Pending save returns the same actual App and Schema. Pending restore returns the
App, source input and declaration/factory receipt. Save never flushes or discards
commands. This queue inspection is separate from the World pending gate.

Plain leaves and duplicate keys across each complete component/resource layout
refuse before projection. Transient leaves are omitted without projection.
Constructed leaves use the actual retained codec and projection and return their
payload and declaration even on invalid projection. A callback may deliberately
transform its returned owner; arbitrary projections are not asserted identities.

Traversal validates column arrays and bounds, performs logical-to-physical
conversion and preserves untouched owners, caches and stamps without lifecycle
writes. Snapshot version 2 includes full saved keys, ordered field presence and
Raw values, stamps, allocator topology and slot states, namespace, clock and
detached lifecycle metadata. Live arrays, Readers and callbacks stay owned by
the application. Detached metadata is not executable restore authority.

## Restore and recovery

Admission derives descriptors from the retained Schema. It validates version,
duplicate full keys, exact ordered field shape, persistence and presence policy,
complete codec values, source namespace/journal agreement, quiescent scopes,
allocator consistency and nonfuture field stamps. Canonical skipped Consumed
slots may be absent from order; they cannot be free or live.

Receiver preparation refuses actual pending work and active execution scopes
before column inspection, constructors or clock-floor mutation. Refusal retains
the actual receiver and captured active tick. Allocation room is checked against
saved progress and entity count before constructors.

Typed reversible factories stage persisted payloads before live mutation.
Construction failure retains recovery and releases staged owners through their
actual undo functions. Transient component payloads are not reconstructed.
Successful publication advances allocator progress monotonically, disposes
receiver entities through canonical commands and returns full saved-key to fresh
handle bindings. Receiver namespace and generations are never overwritten.
Resource replacement returns its complete previous slot and retains transient
resources.

Pre-mutation refusals return actual receiver owners. Unexpected post-clear
refusals are partial. They retain remaining rows, removed owners, receipts,
mapping, source, declarations, factories and undo records. No whole-restore
rollback is claimed. Reconstructed schedules retain registrations, Local,
captures, conditions, handler and actual Reader identities and positions. Resume
executes only after Restored.

## Graph, machine and lifetime scope

Extended detached snapshots include relation groups, committed machine value,
revision and stamp, and named lifetime memberships with complete saved keys.
They exclude live callbacks, pending transition intent, Readers and failure
channel ownership. They are not serialized executable applications.

Graph admission reuses the existing pure hierarchy/cycle validator. Fresh handle
bindings rebuild edges and inverse order. Typed protected-slot publication
preserves receiver namespace, failure channel, sequence and reader allocator,
returns the previous graph and updates cache/stamp at the committed boundary.
Its Ready constructor is trusted framework input, not a proof or gameplay grant.

Machine publication preserves receiver streams and nextStamp, installs admitted
committed value/revision/stamp and clears source pending intent. It does not
replay source history or rebase receiver cursors. Subsequent schedule updates
perform genuine transitions and condition skips.

Lifetime membership admission rejects absent, duplicate and stale full keys
before mutation. The same fresh binding map remaps memberships. Protected-slot
publication preserves receiver namespace, rebuilds the cache, stamps the change
and returns previous members. Source live scope capabilities are not imported.

## Required consumer coverage

The existing [persistence entries](../../examples/system-persistence) retain these
scenarios and complete returned-owner observations.

| Scenario | Required behavior |
| --- | --- |
| Basic and retry | Preserve fields, caches, stamps, Local and captures; map saved keys to fresh handles; retain invalid input and retry valid input on the same App. |
| Pending | Refuse both save and restore before projection, preserving full queued payloads, binding inventories, unapplied IDs and original Reader. |
| Floor and exhausted receiver | Respect saved allocator progress; refuse insufficient room before constructors and resume. |
| Plain | Refuse ineligible World layouts while retaining actual payload and cache. |
| Pooled staging | Release staged owners through actual undo on construction failure; retain complete recovery and permit a valid retry. |
| Extended restore and resume | Preserve receiver machine/failure history and Reader while restoring graphs, committed machine state and memberships; run subsequent updates. |
| Invalid graph or membership | Refuse before receiver mutation, retain input and actual App, then retry valid input. |
| Active execution | Retain the active scope, clock, owners, cursors and both binding roles without constructors or mutation. |

The [historical observations and limitations](https://github.com/dearlordylord/bendvy/blob/431266bac456c5e3cf2f2bbf97d512ae1e7f5a65/docs/design/execution-save-boundary.md)
retain prior backend receipts, oracle corrections and full scene values. They do
not qualify the changed sequential source. Maximum-size metadata export had an
unresolved machine-stack failure; rendering a large allocator does not establish
maximum-size export. Historical timeouts remain nonpasses. Finite outputs do not
prove universal owner identity, exhaustive graph admission or rollback.
