# Relations at the shared command boundary

Relations use the ordinary command queue and complete World publication boundary.
The sequential migration preserves these ownership and authority contracts.
Integrated qualification of the changed application adapters remains pending.

## Graph and authority

`Operation<S>` carries complete World handles for relate, unrelate and reorder.
Reparenting uses relate's source-replacement behavior. Every outcome retains the
original operation; refusal also retains its graph and typed reason.

The framework interpreter receives the actual allocator and namespace from the
same World administration. It checks namespace, generation and Live phase.
Relate and reorder use the existing graph algorithms. Unrelate validates the
source before mutation. An ordinary descriptor refuses hierarchy-only reorder.

Each descriptor occupies its own canonical resource slot. The affine
`execution-relation-store.Store<S,descriptor>` retains its actual World namespace,
graph and failure channel. The graph is the source of truth for forward and
inverse observations. Gameplay receives snapshots through abstract scope methods.
It cannot replace a graph payload or mutate inverse storage directly.

`ProtectedRelation{S,descriptor}` is an access policy independent of persistence.
Generic resource writes reject it. A relation binding carries exact schema,
descriptor, route, payload, view and policy evidence from the complete resource
layout. A matching key or policy tag alone cannot create that evidence.

This source-of-truth contract follows pinned
[Bevy relationships](https://github.com/bevyengine/bevy/blob/ad678262ce53b5d142fe49ee5e08caff6f00ab60/crates/bevy_ecs/src/relationship/mod.rs#L28-L41).
World namespace and hierarchy admission remain explicit Bendvy contracts.

## Queue and publication

`Buffer.Entry.Relation` carries the bound resource route and complete operation.
It shares the queue and retained receipts with component, spawn and despawn
commands. Only a hierarchy selector supplies reorder. Declaration-bound
permissions retain typed relation metadata and a closed resource dispatcher.
No gameplay World callback or second graph implementation is accepted.

The retained command leaf derives publication authority from the same closed
Compilation witness used for construction. Runtime admission checks the actual
Compilation and Local permission before invocation. Raw constructors remain
trusted; no theorem equates arbitrary supplied compilations with their witness.

At publication, the typed dispatcher selects the canonical slot and invokes the
existing interpreter with the actual allocator. Successful mutation refreshes
the graph cache and stamp at the boundary tick. Refusal preserves that cache and
stamp. Receipts retain the complete operation and all handle identities.
Undeclared-route refusal retains the incoming request. No rollback is claimed.

## Failures and readers

The Store retains a failure channel, monotone message sequence and independent
reader allocator. Each affine Reader is branded by schema, descriptor, complete
resource origin and route. Exhaustion returns the actual Store unchanged.
Reader IDs are independent of system registration IDs.

An interpreted same-namespace graph error records a failure message. Namespace
refusal and internal hierarchy admission refusal do not. A rejected graph change
can preserve its graph cache and stamp while updating its owned failure channel.

Reading checks the actual Scope and Store namespaces. Refusal retains the actual
Scope and Reader. Success returns messages, missed count, tick and advanced
Reader. The body adapter retains the Reader and user Local on body error. A false
condition skips that body and cannot advance the cursor.

The shared stream channel rotates two generations on every completed update,
including repeated updates at one World tick. Relation failure retention rotates
only after overall Finished. Stopped and Invalid preserve the returned owners
and pending state.

## Original context and provisioning

Provisioning consumes the unique Factory, constructs resources with its next
namespace and creates the World once. Refusal retains the Factory and actual
constructed owners. The Context comes from that SchemaCreated World and retains
its full-resource equality. It is framework metadata, not a gameplay grant.

A Bound application keeps that original Context. Its checked entry compares it
with the current World before conditions, bodies, publication, clocks or
completion. Refusal returns the complete bound application with ContextRefused.
The full-resource equality transports actual owners across publication. Runtime
route comparison selects an already typed binding and cannot create evidence.

## Evidence and limits

The [historical design and observations](https://github.com/dearlordylord/bendvy/blob/431266bac456c5e3cf2f2bbf97d512ae1e7f5a65/docs/design/execution-relation-operation.md)
retain the earlier implementation sequence and finite scene receipts. They do
not qualify the migration's changed adapters. Existing relation scenes and
failure-reader consumers remain required integrated checks.

The seven relation law subjects and context-law draft remain unapproved and
unproved. They do not establish whole-World preservation, successful graph
mutation, public authority or complete execution. Approved execution helper laws
retain their separate original scope.
